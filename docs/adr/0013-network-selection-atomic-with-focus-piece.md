# Network selection: atomic networks + focus piece via HUD/action detours

**Status:** accepted — relates to [ADR-0012](./0012-network-model-for-dynamic-layouts.md) (the network model this selects over).

Selecting any piece of a `DynamicLayout` network must treat the whole network as one **Logical building** (highlight, copy/blueprint, delete, HUD identity) while still letting the player configure the single piece they clicked. Shapez gates its building HUD purely on `BuildingSelection.Count` — `== 1` renders `HUDBuildingDetails` (the per-building side panel, the only place ExpandableX's connector-slot config **and** grow/shrink buttons appear, injected via the building-modules lookup), `> 1` renders `HUDBuildingSelectionDetails` (the many-buildings panel: blueprint / cut / clear / delete) — and exposes **no** ShapezShifter rewirer seam for either the selection or the HUD parts.

We therefore:

- **Keep the selection atomic per network.** Adding any `Network piece` to `BuildingSelection` adds the whole network; removing any removes the whole network — driven off `ISelection.OnAdded`/`OnRemoved`, active only in the `BuildingsIdle` state. This carries ADR-0012's "a network is only ever created or destroyed as a whole" invariant into the selection, so the selection can never hold a partial network. Whole-network highlight and copy then follow for free (both read the selection).
- **Detour the two HUD parts.** `HUDBuildingDetails` / `HUDBuildingSelectionDetails` gating is detoured so the panel is chosen by **logical-building count** (each network counts as one) rather than raw `Count`, and a single-clicked network renders the per-building panel targeting the **Focus piece** (the clicked member). The focus piece is the only new state and is transient/session-only.
- **Enforce whole-network delete at the action layer.** Every delete gesture (single-panel, mass, area-drag, quick-delete, cut) funnels through `ActionModifyBuildings` with `DeleteBuildingPayload`s; detouring its `IsPossible` to expand any network-member deletion to all members covers them all, including the two (area / quick-delete) that bypass `BuildingSelection` entirely. This absorbs [#10](https://github.com/vdvman1/ExpandableX/issues/10) into [#9](https://github.com/vdvman1/ExpandableX/issues/9).
  - **Neighbour downgrades need a second, earlier detour.** The base game's auto-shaping buildings (belts/mergers/splitters, pipes, wires) re-pick their definition when a building they connect to is deleted; that resolver runs *only* in the mass/area/quick path (`HUDBuildingMassSelection.CreateDeleteAction`), off the same `entries` it builds the delete from. Since our `IsPossible` rewrite happens *after* the resolver has already run on the un-expanded set, neighbours of the auto-added members would be left in stale shapes. So we *also* detour `CreateDeleteAction` to expand its `entries` up front — then both the delete and the downgrade see the whole network. Single-panel delete and cut don't run downgrades at all (base-game behaviour), so the `IsPossible` rewrite is sufficient there.

**This is the codebase's first *behaviour-altering* detour** (`SharpDetour` / Harmony) — the existing session-init detour in `ExpandableXCoreMod` only reads state (a postfix that captures `PlayerActions`/`LocalPlayer`). Everything else used ShapezShifter rewirers plus clean-room implementations; we accept altering game control flow only because no rewirer seam decouples the HUD or selection from `Count`.

## Considered Options

- **Atomic networks + detour HUD gating + focus piece.** *(Chosen.)* The only option that delivers the full single-click experience — whole-network select, highlight, copy, delete **and** simultaneous per-piece config — at the cost of detouring game HUD internals.
- **Mass-panel-only compromise.** Single-click expands to the whole network and shows the many-buildings panel; per-piece slot-config / grow-shrink reached only by some other gesture or deferred to drag handles. Rejected: sacrifices the simultaneous per-piece config that motivates the focus-piece idea.
- **Keep `Count == 1` (no selection expansion).** Single-click selects only the clicked piece so the per-building panel works unchanged; whole-network highlight and copy bolted on via bespoke interceptions. Rejected: those interceptions have no clean seam, and mass-select must expand networks anyway — so the behaviour is inconsistent between single-click and mass selection.

## Consequences

- **Focus is transient, not on the undo stack.** Undo/redo of grow / shrink / slot-swap keep the panel on the focus piece because those actions keep the focus building selected (lightweight recompute: the panel shows iff the focus id is still selected and the selection equals its network). The one sacrifice: undo/redo will not *restore* a focus that a later click cleared. Riding the action stack to fix that was considered and deferred (extra detours, marginal gain).
- **Atomicity is enforced in both directions** and so also catches `HUDBuildingSelectionDetails.NarrowDownSelection` — narrowing a selection onto any network member de-selects the whole network.
- **Copy/paste and highlight fall out.** Copy reads the (atomic) selection; paste re-forms networks through the existing bunch-edit re-networking (ADR-0012); highlight is the game's own `Draw_ExistingSelection`. v1 networks are stateless, so blueprint State capture is a non-issue. The mod is unreleased, so there are no legacy blueprints to migrate.
- **Externally hand-edited partial blueprints can orphan network pieces.** Not defended against (a player who hand-edits a blueprint can equally corrupt a save); a future `ExpandableSimulationSystem` "repair" pass could normalise such cases, but is out of v1 scope.
- **Detours on private/protected HUD internals are version-fragile** — a maintenance cost the rewirer seams avoided, and the reason this is recorded as a decision rather than an obvious step.
- **#10 is absorbed into #9.** "Delete part of a network must delete the whole network" is delivered by the chokepoint guard shipped with the selection model, not as a separate change.
